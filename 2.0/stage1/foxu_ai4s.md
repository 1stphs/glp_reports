# 1. 工作基础：益诺思实验室数据处理与报告自动化平台

**销售产品**：益诺思实验室数据处理与报告自动化平台

## 1.1 自动化报告引擎功能

### 1. 多源文档解析与逻辑一致性管理
- **文档自动化结构化**：系统支持一键上传实验方案（Protocol）、方案变更及相关的实验室原始数据（Excel）。利用 AI 解析引擎将非结构化文档转化为结构化规则库。
- **方案变更支持**：当存在多次方案变更时，系统自动识别条款冲突，通过逻辑覆盖算法确保报告引用的协议内容（如给药剂量、分组信息、采样点等）始终以最新版本为准。
- **跨文档数据校验**：自动比对“方案要求”与“Excel 实际数据”的一致性，在报告生成前预警潜在的数据偏离风险。

### 2. 实验室二次数据解析与语义理解
- **多源数据清洗**：自动化提取实验室设备导出的二次数据，进行结构化处理。
- **深度语义识别**：基于生物医药大模型，对实验参数、异常值说明等非结构化文本进行语义理解，为后续分析奠定基础。

### 3. 报告编排与数据映射
- **自动化大纲构建**：根据项目类型、实验室数据摘要自动生成标准报告大纲。
- **智能数据映射**：建立实验室底层数据与报告章节的动态映射关系，实现“数据驱动文档”，确保每一项实验结果都能精准入库、入表、入文。

### 4. 协同生成与人工审核
- **原子级章节生成**：支持按章节并行自动化生成内容，大幅缩短撰写周期。
- **人机协作工作流**：提供内置编辑器，支持研究人员（SD/PI）对自动生成的段落进行人工审核、在线修订及批注。

### 5. 高保真合规导出
- **模板标准化**：完美兼容益诺思官方报告模板（Word），一键导出符合 GLP/非GLP 规范的最终 `.docx` 报告。

## 1.2 管理功能

- **项目全生命周期管理**：支持基于标准化模板快速立项，提供历史项目资产库，实现历史数据与报告的快速回溯。
- **报告模板管理**：支持报告模板的基准版本管理、信息编辑及启用/停用控制。
- **用户权限与审计**：支持多角色（管理员、撰写人、审核人）权限管理，符合实验室审计追踪要求。

# 2. GLP产品线规划

## 2.1 ‼️ 业务需求1: 毒理学研究 (Toxicology Studies)

- 这是 GLP 业务的核心，旨在评估药物在动物体内的毒性反应。
- 药物开发申报必须环节，也是早期环节；
  - [ ] 单次给药毒性试验（急性毒性）：5-30万
  - [ ] 重复给药毒性试验（长期毒性/亚慢/慢性）：40-400万
  - [ ] 遗传毒性试验 (Genotoxicity)：15-25万
  - [ ] 生殖毒性试验 (Reproductive Toxicology)：单段30-80万；3段全做150-250万
  - [ ] 致癌性试验 (Carcinogenicity)：周期2年 300-500万

## 2.2 ‼️ 业务需求2: 药代动力学（DMPK/TK）

- **业务内容**：虽然很多 DMPK 是在非 GLP 阶段做的筛选，但支持 IND 申报的**毒代动力学（TK）**必须在 GLP 条件下伴随毒理实验进行。
- 报告为申报必须。

## 2.3 业务需求3: 安全药理学 (Safety Pharmacology)

- **业务内容**：评估药物在治疗范围内对重要生理系统（心血管、呼吸、中枢神经）的潜在副作用。
- 非必须项目，业务需求量较前两项弱。

## 2.5 GLP产品规划

**产品本质**：产品本质就是对接不同的业务数据，最终形成规范的，可用于提交的报告。实际在一个业务上跑通，其他业务上直接迭代即可。

- **A. 基础产品：标准报告产出**
  - 毒理学报告
  - 药代动力学报告
  - 安全药理学报告
  - 其他 GLP 报告
- **B. 质控工具**（对已有报告的一致性、逻辑审查；确保符合 SOP 及合规）
- **C. 分析工具**：给出结论及相关引用、论述

## 2.6 GLP产品定位（证明蜂略AI的工业化标准能力）

- **产品定位**：GLP 业务的 CRO 报价 10-300 万之间，但其中 study report 虽然是最终的交付成果，但在其定价结构中占比较低（5%-10%），因此单个利润不高，但报告达到工业标准是 AI 能力的有力验证；很适合用于证明我们的 AI 具备工业能力。
- **客户**：各类承接 GLP 业务的 CRO、CDMO 公司。
- **商业前景**：这个市场已经非常大，而且集中在头部的几家 CDMO 手中，报告的每天产生量客观。能尽快吃下，即可完成这个市场的 AI 教育。使其对 AI 在研发领域的部署产生信任。

## 2.7 产品价值

1. **最主要的亮点是缩短交付周期**
   - 部门 writer 基本一份报告预估需要 21天/人 + 3天审核，但 AI 可以一天产生 100 份报告（算力决定），加上审核周期，4天就可以交付甲方。
   - 加速 CRO 公司的资金回款速度（通常此类业务是里程碑付款）；
2. **其次是减少人力成本**，可以大幅减少甚至完全替代 writer 团队。

## 2.8 GCP与GLP业务差异

| 特征维度 | GLP | GCP |
| :--- | :--- | :--- |
| **核心驱动** | 标准操作程序（SOP） | 临床方案（Protocol）+ 医生判断 |
| **工作流性质** | 线性、重复、高通量 | 分散、协作、突发情况多 |

- **GLP**：标准化；数据干净；主观因素少，工作流线性； 
- **GCP**：非标；数据需要人为干预；非预期情况多，时间非线性；

# 3. GCP产品线规划

## 3.1 产品定位

**产品定位思路**：从 GLP 案例建立信任——过渡到 GCP 需求中标准、重复、线性的部分

## 3.2 ‼️ 业务需求1：Boss对药物的临床结果实时获取/监控（统计分析类产品）

- **产品简述**：统计报告（TFL）实时产生。定期从 EDC 获取数据（excel、SAS数据 or 通过专用软件 API 接口，我认为区别不大），生成简要的统计报告，使得老板能快速获知药物临床的疗效、安全性现状；能够辅助或监察临床及医学工作。效率、准确度高于人工、并能够发现临床试验的运营问题。
- **产品描述**：抓取并分析周期 EDC 信息数据完整度、给出实时的疗效、安全性 TFL 及简要报告。
- **主要输出信息**：
  1. **结论可靠度及改进建议**：根据获得的信息完整度，给出最后结论的可靠程度（缺失信息用默认信息填充补足，如疗效用 SD 填充、安全性用无 AE 填充）。然后给出改进建议：如尽快完善 EDC 信息录入等。
  2. **疗效**：ORR、PFS、OS、（还可以有DCR、DOR）的 TFL，并给出初步结论；【高级版本还可以输出与前一次或前几次比较的趋势变化，提醒注意】。
  3. **安全性**：前10的 AE 的发生率，SAE 发生率，主要导致停药的 AE，3级以上的 TEAE、TRAE。并给出初步结论。【高级版本在加入 AE 的深度趋势分析：提醒值得注意的变化——如发生率快速上升的 AE 事件、导致停药多的 AE 事件、或者某个 site 异常高于其他 site 的 AE 事件】

## 3.3 ‼️ 业务需求2: SAE/SUSAR报告的形成和规范化（PV类产品）

- **产品简述**：PV报告（SAE/SUSAR 的报告、质疑生成）
- **产品描述**：根据研究者填写的初步报告，核查报告逻辑一致性、错误，自动与 argus 数据库信息对比，形成符合 SOP 的最终报告，并对缺失/矛盾信息提出质疑。
- **主要输出信息**：
  1. 读取研究者初步报告，核查报告逻辑一致性、表述错误；修改并对文字、格式规范化重整，以符合 SOP。
  2. 对比 Argus 数据库，审核并补充报告数据。
  3. 根据前2步的审核结果，无法判断的提出质疑，如：应该补充更多的数据、错误的诊断可能性、需要排除非试验药物的混杂因素等等。
  4. 根据 PV 报告类型、严重程度信息，对比 SOP 及国家法规，提醒提交监管的 deadline。

## 3.4 业务需求3: IND/NDA资料的构建、审核（临床注册类产品）

- **产品简述**：IND 资料审核、重整并标准化（包括临床前资料、临床资料）
- **产品描述**：输入已包含信息的数据，临床前如：PK 报告、毒理报告、药学报告；临床如：前期研究的 CSR/统计分析报告；重整并标准化为此次 IND 所需要的标准文档并完成审核，提出需补充信息。
- **主要输出信息**：
  1. 重整、并标准化为可递交的临床前、临床 IND/NDA 注册文档。
  2. 审核相关文档，对缺失信息或需要更新信息进行提示。（如未完成的研究，提供数据太旧；临床前数据和临床数据矛盾；文件间的逻辑错误等）
  3. 根据此次 IND 的目的（可由使用者主观输入，如：首次 IND、关键性临床 IND、其他自定义问题），结合资料，系统生成建议向监管提出的问题（向 CDE 提问的模式应该是只问闭合性问题，且往同意的方向引导，这个也许是 AI 很大的优势），并对问题提供支持性资料；【可作为高级功能】
  4. 【高级功能】根据3的结果，被确认后，生成提交给监管的沟通交流 PPT。

> **批注**：注册产品可以先从审核标准化入手，即根据各已有完整信息的文档进行改写重组为可递交文件。然后再结合 GLP、GCP 的服务迭代为，根据临床前、临床统计数据直接生成递交文档【最终形态】

## 3.5 业务需求4: 数据清洗及生物分析（统计分析产品）

- **产品简述**：数据逻辑核查、医学核查【重难点，现有软件无法做到】；统计分析计划生成【简单、标准化】；统计分析报告【高价值】
- **产品描述**：输入 EDC 数据，完成数据清洗、生成统计分析报告，（这个业务中有很适合 AI 的简单标准化工作，可以先做，难做的部分，逐步迭代）。输入临床试验方案，生成统计分析报告（这个容易且标准化）。
- **主要输出信息**：
  - **数据清洗、分析【难度高、核心价值】**
    1. 输入 EDC 数据，进行逻辑核查，确保信息没有前后矛盾【这部分太美等数据 EDC 公司都能做、现有 SAS 编程也能做】
    2. 进行医学核查：这个很难，要从多个方面积累经验，但是用 AI 是可行的，可以和 CRO 公司合作开发。【价值非常高，非 AI 技术无法做到】
    3. 根据清洗完成的数据，提出质疑，要求补充数据或修改错误数据；
    4. 根据最终清洗后的数据 + 统计分析计划，形成统计分析报告。
  - **输入临床研究方案，生成统计分析报告【难度低、易于快速上线】**

## 3.6 业务需求5：临床QA业务（质量管理产品）

- **产品简述**：产生 SOP 体系，并通过 SOP 体系进行相关文件审查。
- **产品描述**：本身也是质控产品的延伸，且标准化，适合 AI。
- **质量体系建设输出**：
  1. 输入相关联的顶层 SOP（非必须，没有顶层时可以推荐公共模版 SOP）+ 输入实际业务的流程描述；
  2. 根据1 输出此业务的 SOP，并结合公共 SOP 数据、国家法规，CDE 指导原则给出评价建议。
- **临床质量稽查**：
  1. 根据业务 SOP 及顶层 SOP + 国家相关法规、CDE 指导原则，审查文档。
  2. 给出具体文档的质量问题，以及相关依据。
  3. 给出解决文档质量问题的初步建议。
  4. 质量以外的文档问题（逻辑一致性、错误、矛盾）

## 3.7 业务需求6：医学、临床文档创建、审查（医学、临床运营产品）

- **产品简述**：对方案、IB、ICF 等关键医学文档；临床监察计划 CMP、项目管理计划 PMP 等临床运营文档的审查。
- **产品描述**：IB、ICF、CMP、PMP 均能够通过方案+SOP 创建；临床方案是核心，难以立刻达到高质量创建，但是这里有【非常强烈的核心需求是对方案的审查，面向 Boss 直接汇报】
- **方案审查输出**：
  1. 根据质量稽查产品，对方案进行 SOP 审核（但大多数公司可能没有方案 SOP、或者非常简单），所以这一步只是初筛；
  2. 根据质控产品，对方案完整性进行审核（逻辑一致性、错误、矛盾）；
  3. 【核心价值，高利润】根据数据库相似适应症、相似药物靶点方案，对方案进行评估。最终输出方案评价报告。
  4. 报告纬度：适应症人群选择宽/窄；入排标准的同行比较差异；病理采集差异；采血项目差异；采血点疏密；流程表的时间窗差异；临床检查项目差异；疗效评估的周期差异；探索性 biomarker 差异；分层分析设计的差异；对照组的药物选择差异；盲法差异；统计假设的差异。【可初级版本逐步迭代出完整功能】
- **其他文档的创建/审核输出**：
  1. 根据方案、SOP（以及数据库相关案例知识），创建 ICF、CMP、PMP 文档。【IB 的生成为高价值文档（和注册产品的技术路径一致）】
  2. 用 QA 稽查产品 + 质控工具对文档进行审核，并输出改进后版本及修订总结。
