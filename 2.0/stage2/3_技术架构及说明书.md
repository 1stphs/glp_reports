### 1. 总体架构图

**文字版架构图**

```
用户项目工作台 (Next.js)
   ↓ (Webhook / API)
n8n (外层可视化编排层)
   ├── 项目创建向导（对话式/表单式）
   ├── 文件上传 + MinerU 7B OCR预处理
   ├── LIMS集成 + BioLab Automation增值服务开关
   ├── 电子签名 + 通知推送
   └── Feature Flags控制（Core / 增值服务 / Enterprise）
         ↓
LangGraph微服务集群 (核心业务大脑)
   ├── 4个Stateful Agent（Bioanalyst / Writer / Scientist / QA）
   ├── Pydantic AI结构化输出守门员（所有Node强制）
   ├── 中央Router（小模型优先 + 大模型兜底）
   ├── Heartbeat Scheduler（自主周期任务）
   └── Spawn SubAgent Tool（动态子任务）
         ↓
PicoClaw Virtual SD (轻量协调层，虚拟SD/PM)
   ├── 监控LangGraph状态
   ├── 协调人机协同团队（数字员工 + 真人用户）
   ├── 动态任务生成与提醒
   └── 通过HTTP/gRPC与LangGraph双向通信
         ↓
共享持久层
   ├── OpenViking统一Workspace（PicoClaw风格目录结构 + L0/L1/L2 + Skills三层）
   ├── PageIndex文档树索引
   ├── GLP专属小模型集群（3个）
   └── E2B沙箱（计算隔离）
         ↓
PostgreSQL (审计日志 + 项目元数据 + 用户自定义Skills)
```

### 2. 模块职责划分

**n8n（外层可视化编排层）**  
- 负责所有用户可见交互和企业系统对接  
- 项目创建向导（支持对话式/表单式）  
- 文件上传 + MinerU 7B OCR预处理  
- LIMS/Provantis集成（BioLab Automation增值服务）  
- 电子签名、通知推送、Feature Flags  
- 与LangGraph通过HTTP Webhook通信

**LangGraph微服务（核心业务大脑）**  
- 4个Stateful Agent的核心执行引擎  
- Pydantic AI强制结构化输出（所有Node）  
- 智能路由决策（小模型优先、大模型兜底）  
- 动态任务生成与子任务spawn  
- Heartbeat Scheduler（周期性检查）

**PicoClaw Virtual SD（轻量协调层）**  
- 虚拟SD/PM角色，常驻轻量实例  
- 监控项目整体状态  
- 协调人机协同团队（数字员工 + 真人用户分配）  
- 动态任务生成与用户提醒  
- 所有协调行为记录到OpenViking

**OpenViking（统一Workspace）**  
- PicoClaw风格文件系统（memory / sessions / state / heartbeat / subagents / skills）  
- L0/L1/L2渐进式加载  
- 三层Skills加载（workspace / global / builtin）  
- 所有Agent和Virtual SD共享

**GLP专属小模型集群**  
- Protocol & Data Extractor  
- ToxPath Reasoner  
- GLP Compliance Guardian

### 3. 数据流与状态机

**核心数据流（项目创建 → 执行 → 交付）**  
1. 项目创建 → n8n向导 → LangGraph生成初始任务列表（标注数字员工/真人）  
2. 用户确认团队（数字员工 + 真人用户） → Virtual SD启动heartbeat  
3. 执行过程中：  
   - LangGraph动态生成子任务（例如Writer生成大纲后自动创建章节子任务）  
   - Virtual SD监控并推送真人参与提醒  
4. 所有输出通过Pydantic AI结构化 → 存入OpenViking workspace  
5. Virtual SD最终把关 → n8n触发导出 + 审计包生成

**状态机设计**  
- LangGraph State包含：project_id、team_composition（数字+真人）、current_phase、dynamic_tasks  
- 所有状态持久化到OpenViking，实现断点续跑  
- Virtual SD通过HTTP轮询/事件监听LangGraph状态

### 4. 关键技术决策

**4.1 小模型路由策略**  
- 系统优先使用小模型以平衡成本与性能  
- 通过LangGraph中央Router + Pydantic AI决策  
- 必要时自动切换大模型（Gemini Pro / Claude）确保业务稳定交付

**4.2 Skills开放机制**  
- Enterprise用户可在AgentOps中修改、测试、发布部分Skills  
- 所有自定义Skills必须经过Virtual SD审核 + Pydantic AI验证后生效

**4.3 Virtual SD融合**  
- 单轻量PicoClaw实例作为协调层  
- 负责heartbeat、spawn、团队协调、人机任务分配  
- 不参与核心计算，仅协调LangGraph主流程

**4.4 安全性与合规**  
- 所有heartbeat/spawn记录强制进入OpenViking + PostgreSQL，不可篡改  
- E2B沙箱隔离所有计算  
- MinerU 7B OCR作为文档预处理前置

### 5. 部署架构

**开发环境**  
- Docker Compose一键启动（n8n + LangGraph + OpenViking + PicoClaw + PostgreSQL + MinerU 7B）

**生产环境**  
- Kubernetes多租户部署  
- 每个租户独立OpenViking volume  
- Virtual SD可独立水平扩展

**监控与日志**  
- Prometheus + Grafana（Agent负载、小模型调用率、heartbeat频率）  
- LangSmith风格全链路tracing（每一步输入输出哈希）
