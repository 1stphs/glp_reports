### 二、 用户与数字员工的交互范式 (Interaction Flow)

用户与 AI 的交互绝不是简单的“你问我答（Chat）”，而是基于文档上下文的**“指令下达 -> 过程监控 -> 局部干预 -> 签字确认”**。

我们以一个包含异常数据的毒理学项目为例，走通这个交互流：

**Step 1：异步委托与过程监控 (Delegation & Monitoring)**

* SD 立项并上传资料后，**AI Bioanalyst** 开始提取和清洗数据。
* SD 不需要盯着屏幕。平台通过类似钉钉/企微的集成发送通知：“*项目 A 数据清洗完毕，**AI QA** 发现 3 处方案偏离，请前往处理。*”
* **交互点**：SD 登录平台，在“任务指挥中心”看到红色的预警卡片，点击直接跳转到异常数据位置进行确认。

**Step 2：上下文中的定向唤醒 (Contextual @Mentions)**

* 当 **AI Writer** 生成了初稿，SD 进入“沉浸式审查工作台”阅读。
* SD 读到一段病理切片的分析，觉得结论不够深入（这是 **AI Scientist** 负责的部分）。
* **交互点**：SD 选中该段落，直接在旁边弹出的批注框中输入：“*@Scientist，请结合对照组的本底病变发生率，重新论述这个异常是否具有毒理学意义，并补充相关文献引用。*”
* AI Scientist 仅针对这一局部上下文进行重新推理和生成，不干扰全文。

**Step 3：冲突裁决 (Conflict Resolution)**

* 假设发生了一次“方案变更”。
* **AI QA** 拦截了流程，在工作台右侧弹出提示：“*QA 警报：AI Bioanalyst 提取的采样时间为 2h，但最新方案变更已修改为 4h。*”
* **交互点**：SD 在界面上看到两个并排的数据卡片，点击“采纳变更方案”，系统自动让 AI Writer 刷新相关段落。人类扮演的是“法官”角色。

**Step 4：放行与责任交割 (Sign-off & Accountability)**

* 报告定稿。SD 必须进行最后一步交互：**电子签名 (E-Signature)**。
* **交互点**：系统强制要求 SD 输入二次密码，声明确认。此时，这份报告的所有权从“数字员工”正式转移给“人类专家”，系统一键导出高保真的合规 `.docx` 报告。

**Writer 与 Bioanalyst 的协作模式深度探讨**

你的澄清非常关键：**当前工作基础的核心价值不是“让Bioanalyst把Excel全部数据都处理完再交给Writer”**，而是**“让Bioanalyst先把所有原始表格‘认出来’并结构化，然后通过智能映射决定它们到底该出现在报告的哪个章节”**。  
这其实是一个**“数据发现 → 结构化 → 章节规划 → 叙事填充”**的流水线，而不是简单的“数据处理员把表格做好后扔给Writer”。

既然你明确说“之前工作基础思路只是参考，不一定是合理的”，我下面直接**推倒重构**，给出**工业级、可直接落地的Writer-Bioanalyst协作架构**。这个架构完全围绕你描述的“预定义模板大纲全集 + Excel表格解析 + LLM章节规划+映射”来设计，同时完美嵌入我们之前讨论的4位数字员工体系、沙盒安全机制和GLP合规要求。

### 1. 重新定义两个角色的核心边界（避免重叠与低效）

| 角色 | 核心使命 | **绝对不做**的事 | 输出物（给对方的交接件） |
|------|----------|------------------|--------------------------|
| **AI Bioanalyst** | “表格的发现者与结构化专家”<br>只负责把Excel里的每一张表“读懂、清洗、打标签” | 不决定章节、不写任何文字、不排版 | 1. 结构化表格对象列表（带元数据）<br>2. 每张表的“语义标签集”（e.g., `pk_parameters_concentration`, `toxicology_clinical_chemistry`）<br>3. 表格质量评分（完整性、异常值标记） |
| **AI Writer** | “报告的建筑师与文字裁缝”<br>负责大纲最终确定、语言转译、表格插入、段落生成 | 不直接解析原始Excel、不做数值清洗 | 1. 最终报告大纲（章节树）<br>2. 已完成语言转译+表格占位符的章节草稿<br>3. 插入指令（“第3.2节插入Table_07”） |

**关键原则**：Bioanalyst只产出**结构化资产**，Writer只消费**结构化资产**并产出**叙事资产**。中间有一个**显式的“映射与规划”环节**（可由Writer主导，也可独立Coordinator Agent）。

### 2. 推荐的端到端协作流水线（6步，LangGraph可直接实现）

```
Protocol + Excel → Bioanalyst → 结构化表格包 
                     ↓
               映射规划模块（LLM主导）
                     ↓
               Writer → 带表格的报告草稿 
                     ↓
               QA + Scientist（可选）→ 最终放行
```

**第1步：Bioanalyst预处理（你的核心优势强化）**  
- 一键上传Protocol（PDF/Word）+ 多份Excel。  
- 使用你已有的“AI解析引擎 + 沙盒”（Extractor + Critic + Pydantic）先把Protocol转成结构化规则库（给药、采样、分组等）。  
- 同时解析所有Excel：  
  - 自动识别每张表（sheet名、表头行、数据类型、单位）。  
  - 提取元数据：表标题、维度（行=动物ID？列=时间点？）、关键列（Concentration、AUC、BW等）。  
  - 输出：一个**统一表格资产包**（JSON + Parquet），每张表带唯一ID和语义标签（用RAG+Classifier Agent打标签）。  
- 输出示例：  
  ```json
  {
    "tables": [
      {"id": "TBL_001", "semantic_tags": ["pk_concentration_time", "plasma"], "shape": [48, 12], "confidence": 0.98}
    ]
  }
  ```

**第2步：模板大纲加载（你的“全集目录”落地）**  
- 系统预置**每个模板的主大纲树**（你说的“目录大纲全集”）。  
  示例（生物分析单场点PK模板）：  
  ```
  1. 引言
  2. 材料与方法
     2.1 试验设计（从Protocol规则库拉）
     2.2 分析方法
  3. 结果
     3.1 给药信息
     3.2 血浆浓度-时间数据 → 这里必须插入浓度表
     3.3 TK参数表
  4. 讨论与结论
  ```

**第3步：LLM章节规划与表格映射（最关键的“智能中枢”）**  
- 由**Writer**（或独立Coordinator Agent）主导：  
  输入 = Protocol规则库 + Bioanalyst的表格资产包 + 当前模板主大纲。  
  输出 = **最终定制化大纲** + **表格→章节映射表**。  
- 提示词核心（沙盒内）：  
  “你现在是GLP报告架构师。严格按照模板主大纲结构，结合Protocol的具体试验类型，生成最终章节列表。对于Bioanalyst提供的每一张表，决定它最适合插入哪个章节（必须是结果章节下的子节）。如果某章节缺少必要表格，标记为‘需补充’（触发Scientist或人工）。”  
- 使用**动态Pydantic Schema**强制输出：  
  ```python
  class ChapterPlan(BaseModel):
      chapter_id: str
      title: str
      required_tables: List[str]   # TBL_001, TBL_007...
      missing_data_flag: bool
  ```
- 多Agent增强：Extractor（规划章节）+ Critic（核对是否所有表格都被分配，且无重复）。

**第4步：Writer并行填充**  
- Writer拿到最终大纲 + 映射表 + 表格资产包。  
- 并行生成每个章节：  
  - 把Protocol“将来时”→“过去时”。  
  - 在对应位置插入表格（用python-docx或Mammoth生成占位符，后续高保真导出）。  
  - 生成叙述性文字（“如表3.2所示，...最高浓度为...”）。  
- 优势：Writer完全不碰原始Excel，只操作**干净的结构化资产**，速度快、幻觉风险低。

**第5步：双向反馈闭环（关键防崩机制）**  
- Writer生成过程中若发现“映射表里某个章节缺表”，自动发消息给Bioanalyst：“第3.4节需要毒性分级表，请重新扫描Excel或标记为缺失”。  
- Bioanalyst可触发“二次解析”或直接标记Red Flag交给人工。

**第6步：交接给QA与Scientist**  
- Writer输出“带表格的完整草稿”→ QA做一致性+溯源校验。  
- 复杂章节（Discussion）→ Scientist接手补充结论。

### 3. 这种协作模式的优势（对比你原工作基础）

- **比原基础更合理的地方**：

  每一步都有溯源：表格ID→章节ID→最终.docx页码。QA可一键回溯“为什么TBL_023被放到了4.2节”。

### 4. 潜在风险与对策（GLP级严谨）
