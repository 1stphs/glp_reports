### 1. 用户画像与用户旅程（User Personas & Journey）

#### 1.1 主要用户画像

**Persona 1：SD/PI（研究负责人，核心决策者）**  
- 年龄：40-55岁  
- 背景：毒理学/生物分析博士，负责多个GLP项目最终签发  
- 痛点：进度不可控、异常发现晚、审批工作量大、需要快速组建人机协同团队  
- 目标：通过对话式或表单式快速创建项目，清晰看到任务分配（AI vs 真人），及时收到参与提醒  
- 使用频率：每天1-3次，主要使用概览页、Issues & Approvals、数字员工workspace

**Persona 2：生物分析主管 / Writer（执行层）**  
- 年龄：30-45岁  
- 背景：日常负责生物分析报告撰写与数据映射  
- 痛点：重复的二次数据处理、章节映射耗时、需要清晰的任务分工提醒  
- 目标：项目创建后立即看到初始任务框架，并在执行中动态收到子任务和补充提醒  
- 使用频率：高频，主要使用任务页、交付物页

**Persona 3：毒理学家（复杂推理用户）**  
- 年龄：35-50岁  
- 背景：负责毒理报告Discussion与NOAEL判定  
- 痛点：病理描述提炼困难，需要AI与真人协同的任务动态清晰可见  
- 目标：项目启动后快速确认初始任务，并在执行中动态收到补充子任务提醒  
- 使用频率：中频，主要使用交付物页、嵌入式聊天

**Persona 4：QA经理（合规把关者）**  
- 年龄：38-52岁  
- 背景：负责GLP合规审查  
- 痛点：跨文档一致性检查工作量巨大，需要系统主动提醒动态参与点  
- 目标：清晰看到初始任务框架，并及时收到执行中的补充审核提醒  
- 使用频率：中高频，主要使用Issues & Approvals、审计日志

#### 1.2 典型用户旅程（4分钟完成一份报告 - 已按您的3个需求深度重构）

**主旅程（SD/PI视角，完整覆盖项目创建 → 初始任务 → 动态执行）**

1. **仪表盘 → 新建项目**  
   - 用户在仪表盘点击醒目“新建项目”按钮。  
   - 进入**项目创建流程**（向导页，支持**对话式和表单式双模式切换**）。  
     - **表单式**（默认，老手快速模式）：分步填写项目名称、Study ID、项目类型（生物分析/毒理学），直接上传Protocol和Excel二次数据。  
     - **对话式**（新手友好模式）：Virtual SD以聊天形式引导：“请告诉我项目名称和类型”，用户可自然语言输入，同时支持拖拽上传Protocol和Excel数据。  
   - 在创建过程中，Virtual SD实时推荐并让用户确认**人机协同团队组成**：  
     - **数字员工**：默认Bioanalyst + Writer + QA + Virtual SD（毒理项目自动添加Scientist），用户可勾选/调整。  
     - **真人用户**：默认推荐SD/PI（本人）、生物分析主管、QA经理，用户可从组织通讯录中搜索添加其他角色（例如毒理学家、项目助理），并指定权限（审批/执行/查看）。  

2. **项目创建完成 → 生成初始任务列表**  
   - 项目创建成功后，系统立即跳转到项目工作台的**任务页**。  
   - Virtual SD首先生成**初始高层次任务列表**（LangGraph根据项目类型和Protocol自动生成主任务框架，例如“1. 数据解析、2. 大纲生成、3. 章节填充、4. 合规审查”）。  
     - 每条任务明确标注：  
       - **数字员工负责**（绿色标签，例如“Bioanalyst：解析Protocol和Excel规则库”）  
       - **真人参与**（蓝色标签，例如“SD/PI：最终审批Discussion”）  
   - 用户必须**逐条确认或调整**初始任务列表（可拖拽顺序、标记优先级、指定真人负责人）。  
   - 用户点击“确认并启动”后，Virtual SD正式调度执行。

3. **执行过程中动态生成子任务与提醒**  
   - 系统采用**动态任务生成机制**（LangGraph条件边 + Virtual SD协调）：  
     - 执行过程中，Agent会根据实际结果动态生成子任务。例如：Writer生成大纲后，才自动生成“各章节的子任务列表”；Bioanalyst发现数据缺失时，动态spawn补充任务。  
     - Virtual SD实时监控并更新任务页，新增子任务自动高亮，并标注负责人（数字员工或真人）。  
   - **需要用户参与的任务**会触发主动提醒：  
     - 工作台内高亮 + 倒计时  
     - n8n推送企业微信/钉钉/站内消息（例如“项目TOX-001的Discussion子任务已生成，请SD/PI审核”）  
     - 嵌入式聊天：Virtual SD主动@用户：“发现需要补充采样点数据，请确认”  
   - 用户点击提醒后直接跳转到对应任务/交付物/Issues页。

**次要旅程（生物分析主管视角）**  
重点在项目创建时选择对话式模式快速上传数据，创建完成后立即在任务页确认初始任务框架（含真人任务分配），并在执行中动态收到子任务提醒。

### 3. 页面流程与Wireframe（核心部分）

#### 3.1 项目创建流程（重点展开）

**流程步骤**（向导式，3步完成，支持对话式/表单式切换）

1. **步骤1：基本信息与团队组建**  
   - 顶部切换按钮：“表单模式 / 对话模式”  
   - 表单模式：填写项目名称、Study ID、Sponsor、项目类型  
   - 对话模式：Virtual SD聊天引导输入  
   - **重点**：实时显示并让用户确认**人机协同团队组成**：  
     - 数字员工部分（默认推荐，可勾选）  
     - 真人用户部分（默认推荐SD/PI本人、生物分析主管、QA经理；支持从组织通讯录搜索添加其他角色，并指定权限）  

2. **步骤2：数据上传**  
   - 拖拽上传Protocol + Excel二次数据（明确属于创建过程）  
   - MinerU 7B OCR实时处理扫描文件  
   - Virtual SD显示“正在初始化workspace并组建团队”  

3. **步骤3：确认与启动**  
   - 显示初始高层次任务列表预览  
   - 大按钮“确认团队并启动项目” → 跳转到项目工作台任务页

**Wireframe描述**  
- 左侧进度条（1/2/3）  
- 右侧实时预览区：团队组成卡片（数字员工 + 真人用户列表） + 上传文件列表  
- 对话模式时，右侧聊天窗口与左侧表单可切换

#### 3.2 项目工作台（重点展开）

**整体布局**  
- 左侧固定侧边栏：7个Tab + 项目切换器  
- 主内容区：根据Tab切换内容  
- 右下角固定“数字员工快捷栏”（5个头像 + 状态指示灯）  
- 顶部：面包屑 + Virtual SD今日工作摘要条

**7个Tab详细Wireframe**  
- **概览**：进度环形图 + Virtual SD今日总结卡片  
- **任务**：Gantt图 + 任务卡片列表（初始高层次任务 + 动态生成的子任务实时更新）  
- **交付物**：版本列表 + “打开workspace”按钮  
- **Issues & Approvals**：Red Flag列表 + 电子签名区

#### 3.3 数字员工workspace（重点展开）

**定位**：PicoClaw风格的“数字员工个人办公室”，是产品形态的核心亮点。

**触发方式**  
- 交付物页每项右侧“打开workspace”按钮  
- 点击数字员工头像 → 弹出workspace视图（默认显示当前项目）

**页面布局**  
- 左侧目录树（PicoClaw风格）：memory / sessions / state / heartbeat / subagents / skills  
- 右侧内容区：选中目录后显示详细内容（heartbeat记录、已spawn子Agent、用户自定义Skills）  

**交互亮点**  
- 可视化检索轨迹  
- Virtual SD专属标签：所有协调行为高亮显示  
- Enterprise用户可直接在skills目录修改、测试、发布SKILL.md

### 1. AI Medical Writer (医学撰写员)

**定位**：极其严谨的“文字裁缝”与格式管家。
**工作职责**：

* **句法级重构**：专门负责将实验方案（Protocol）中的“计划语言”（将来时/主动语态）无缝转译为“报告语言”（过去时/被动语态）。
* **大纲与骨架搭建**：根据项目类型，自动生成标准报告的大纲。
* **SOP 级规范填入**：从其他员工那里接收零散的结论，将其映射并拼装为符合 SOP 规范的标准段落，实现零偏差的文本生成。
* **高保真排版**：负责最终输出兼容益诺思等官方模板的 `.docx` 报告。

### 2. AI Bioanalyst (生物分析专员 - 专注定量数据)

**定位**：不知疲倦的数据处理狂魔，您**当前工作基础的核心化身**。
**工作职责**：

* **掌控 18 个核心模版**：完美覆盖生物分析（BA）和药代动力学（PK）的单场点/多场点 RD、TD、EX 等标准化实验。
* **数据清洗与映射**：自动化提取实验室仪器导出的二次数据（如 Excel 浓度数据），进行清洗并与 Protocol 规则进行比对。
* **动态制表**：生成复杂的统计分析表格和数据矩阵，并精准地将这些“结构化数字”喂给 Writer 员工去写报告。

### 3. AI Scientist (科学研究员 / Sci)

**定位**：拥有深度领域知识的“医学智囊”，主攻**非标与推理**。
**工作职责**：

* **攻坚毒理学 (Toxicology)**：处理单次/重复给药毒性、遗传毒性等极其复杂的实验项目。
* **多模态事实提炼**：阅读非结构化的病理切片描述、动物体征临床观察记录等。
* **科学因果推理**：负责撰写报告中最核心、最难的“讨论与结论（Discussion & Conclusion）”部分。判断异常数据是药物导致还是本底背景，并提供支持性论述。它不处理枯燥的排版，只输出硬核的医学逻辑。

### 4. AI QA (质量保证稽查员)

**定位**：冷酷无情的合规守门员，悬在所有流程上方的“监察之眼”。
**工作职责**：

* **跨文档一致性校验**：自动比对“方案要求”与“实际数据”的一致性，预警数据偏离风险。它独立于其他员工，对生成的内容进行二次交叉验证。
* **三维溯源守护者**：它负责建立和维护细粒度的数据溯源视图。确保前三位员工产出的每一句话、每一个数据，都能清晰地追溯到源头。
* **标准审查（法规切换）**：它脑子里装载了 FDA 21 CFR Part 11、NMPA、OECD GLP 甚至 CDISC SEND 的法规数据库。负责审批最终文档是否满足特定的监管合规要求，记录系统级审计追踪。

### 这种“数字员工”架构的绝对优势：

1. **极度清晰的边界解耦**：如果生物分析的数据出错了，就去调优 Bioanalyst 的规则；如果文字排版出错了，就去修改 Writer 的 Prompt。互不干扰，研发路线异常清晰。
2. **人机协作更加自然**：在前端的工作台中，人类的 SD（专题负责人）更像是一个“项目经理”。SD 可以在系统中看到：*“Bioanalyst 已经提交了数据，Writer 正在撰写草稿，QA 刚才提出了 3 个数据不一致的警告。”* 这种交互体验 是革命性的。
3. **顺滑的 GCP 扩展**：未来做临床业务规划 时，底层逻辑不用推倒重来，只需要“新招几名员工”即可，比如招一个 **AI CRA（临床监察员）**负责 PV 报告自动化，招一个 **AI Regulatory Affairs（注册专员）**负责 IND 资料重整。
